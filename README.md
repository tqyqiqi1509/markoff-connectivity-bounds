# Explicit connectivity bounds for Markoff graphs

Computational supplement for the unchanged 31-page manuscript *Explicit
connectivity bounds for Markoff graphs*. The stated prime ranges are
`5 <= p <= 10^66` and `p >= 8 * 10^152` for the graph generated by the three
Vieta involutions on the nonorigin Markoff surface.

**Fixed version:** [v1.0.0](https://github.com/tqyqiqi1509/markoff-connectivity-bounds/releases/tag/v1.0.0).
The release includes the large content objects; a source-only Git clone is not
the complete computational supplement. `data/RELEASE_ASSETS.json` gives every
asset's SHA-256. `data/PATH_MAP.json` maps every retained original logical path
to its repository object or release member, with a selection reason and digest.
The two ranges do not cover all primes.

## Contents and traceability

- `source/`: original mathematical source programs, preserving their paths and bytes.
- `data/objects/`: compact certificates, inputs and recorded determinant journals.
- Release `proof-data-*.zip`: large matrices, source rows and spectral node streams,
  stored once per distinct SHA-256; each ZIP member is `objects/<sha256>`.
- `indices/general_rank_inputs.json` and `.csv`: the 57 parameters, actual N,
  strict characteristic gates, original certificate paths and hashes.
- `indices/POINTWISE_BATCHES.json`: all 90 batches covering the 1,775 pointwise candidates.
- `tools/`: portable entry points and small independent checks.
- `indices/PORTABILITY_CHANGES.json`: exact original-to-adapter changes.
- `indices/FROZEN_PAPER.json`: hashes of the unchanged paper files; the manuscript
  itself has not been edited by this packaging operation.
- `docs/PAPER_DEPENDENCIES.md`: paper claim to input/program map.
- `docs/NUMERICAL_MARGINS.md` and `.json`: all twelve endpoint margins and the
  additional integer gates requested in the submission feedback.
- `verification/`: actual replay receipts and independent agent review scopes.

Historic names, absolute paths, timestamps and status strings inside immutable
certificates record their origin. They are not instructions to execute, and a
historical `accepted` label is not independent mathematical certification.
Superseded exploratory routes, third-party PDFs, credentials, caches and
compiler-produced historical executables are not distributed.

## Environment

Use Python 3.11 or newer with assertions enabled (**never `python -O`**).
The standard-library stages require no Python packages. Analytic interval
stages use `python-flint==0.9.0` (Arb). The parallel rank verifier requires
Linux/WSL (`fcntl` and `fork`). C++ stages need a C++17 compiler, GMP development
headers/libraries, and any FLINT dependencies imported by the selected verifier.
No software dependency or runtime cache is bundled as research data.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python tools/restore_inputs.py --output work
```

For an offline restore, download **all** release assets to a directory and use:

```sh
python tools/restore_inputs.py --asset-dir /path/to/assets --offline --output work
python tools/verify_artifacts.py --asset-dir /path/to/assets --work-dir work --output artifact-review.json
```

Restoration refuses an existing output directory, validates asset and object
hashes, and writes regular files plus internal aliases. It never links writable
work files to the repository or immutable release inputs. Allow disk space for
the downloaded archives, unique restored data, and fresh replay outputs.

receipts under `work/root_logs`; a restored work tree is a disposable replay
copy, not the immutable archive. Use another restore for a second clean run.

## Fresh large determinant computations

`finite-records` does **not** recompute the 1,775 determinants. To recompute one
indexed batch using the two original determinant implementations:

```sh
python tools/run_checks.py pointwise-batch --work-dir work --output-dir replay/batch000 \
  --batch agents/finite_extension_round20/batch_000_d173
```

Repeat for every entry of `indices/POINTWISE_BATCHES.json` to regenerate all
pointwise determinants. This compiles the bound C++ source and invokes the
GMP implementation plus the separate FLINT determinant, using the same source
rows. It changes only the disposable work tree. Source-row regeneration is a
further stage; the original generators and their parameter records are retained.

For the five large new prime parameters, for example:

```sh
python tools/run_checks.py general-modular --work-dir work --output-dir replay/d163 \
  --d 163 --workers 4
```

This reconstructs the matrices from the saved integer source and performs new
determinants at certified Proth primes until the CRT modulus exceeds twice the
Hadamard bound. It is expensive. It is distinct from checking a saved journal.
For the earlier parameters and composite parameters, use their corresponding
source formats and verifiers as described in `docs/GENERAL_RANK_REPLAY.md`;
do not apply the five-parameter interface indiscriminately.

## Verification boundary

Artifact hashes establish byte identity. Replay receipts establish only the
scope stated for that run. Neither establishes a proof-assistant certification,
external peer review, or complete human verification. The publication audit
does not claim that all 57 general rank computations and 1,775 pointwise
determinants were regenerated from raw polynomials during packaging. The
complete retained source, inputs, source divisions, minors and journals are
provided so these expensive computations can be examined and rerun.

The ordinary constants 21718 and 135 retain the older complete spectral and
integer-recursion computations; their sources and original input streams are
included, and their replay instructions are in `docs/ORDINARY_MOMENTS.md`.
All theoretical reductions remain in the frozen manuscript. External cited
mathematical results and the arithmetic libraries retain their stated roles.
